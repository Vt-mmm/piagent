v1.12.0 · 2026-10-06

@ tới mọi folder, skill dùng bằng /, và test chạy được trong sandbox công ty

Chỉ cho agent đúng file hay folder cần đọc, dùng lại skill và command đã có, và để agent tự chạy unit test lẫn integration test của project.

@ file và folder

Gõ @ trong khung chat để chọn file, folder của project; gõ ~/ hoặc / để chọn folder khác trên máy. Agent đọc được folder ngoài project, chỉ đọc; file ẩn trong home, ~/Library và file chứa credential vẫn bị chặn.

Giữ tin nhắn đang soạn

Tin nhắn gõ dở ở mỗi cuộc trò chuyện và ở khung chat mới vẫn còn khi chuyển sang cuộc trò chuyện khác hay tải lại trang, cùng file đã đính kèm.

Skill và command

Skill và command trong .claude, .codex, .agents và .pi của project và trên máy dùng được ngay: model thấy danh sách skill, gõ / ở đầu tin nhắn để chọn /command hoặc /skill:tên.

Test trong sandbox công ty

Cache package giữ theo project (npm, pnpm, pip, uv, Go, Cargo, Gradle, Maven, NuGet…), server và database trên localhost, Xcode đã chọn, JDK, .NET. Chạy piagent studio --doctor để xem ngôn ngữ nào sẵn sàng. Docker và iOS Simulator chưa dùng được trong sandbox.

v1.10.0 · 2026-10-05

Main agent hỏi lại khi chưa rõ, subagent được phản biện brief

Khi yêu cầu còn để ngỏ một quyết định, main agent hỏi bạn bằng thẻ câu hỏi có lựa chọn đánh số thay vì đoán. Subagent được nêu bằng chứng khi brief lệch yêu cầu, và bất đồng lần hai thì bạn quyết. Hết quota hay patch quá lớn không còn làm dừng việc.

Hỏi lại bằng lựa chọn

1–4 câu hỏi, mỗi câu 2–4 lựa chọn đánh số, luôn có "Khác" để tự nhập và "Để agent tự quyết". Bấm số để chọn, Enter để gửi. Bấm Dừng giữa chừng thì khi "tiếp tục", agent hỏi lại chứ không chọn thay bạn.

Subagent phản biện brief

Subagent đọc nguyên văn yêu cầu và plan trước brief. Brief sai hoặc lệch yêu cầu thì subagent nêu bằng chứng và main agent phải trả lời. Bất đồng lần hai, hội thoại ghi "Cần bạn quyết".

Chạy tiếp khi hết quota

Subagent hết quota hoặc tài khoản đang nghỉ sẽ chạy lại trên model dự phòng của Harness. Patch trên 120 KB được review theo từng phần rồi gộp findings.

Bấm Enter hai lần, hoặc Enter rồi bấm nút gửi, trước khi trang kịp cập nhật vẫn chỉ tạo một cuộc trò chuyện và gửi một tin.

Subagent đọc tối đa 20.000 ký tự mỗi trang, mặc định 12.000. Main agent vẫn đọc được tới 100.000 ký tự.

v1.9.2 · 2026-10-03

Việc trên web để subagent nghiên cứu làm, khung chat không giật

Khi Harness có subagent nghiên cứu, main agent không còn công cụ web. Search và đọc trang chạy trên model của subagent nghiên cứu.

Mỗi kết quả search ghi rõ engine đã trả lời: Tavily, Exa hay Parallel qua search pool của công ty, hoặc search riêng của nhà cung cấp model.

v1.9.1 · 2026-10-03

Subagent khảo sát và xác minh, tìm web cho mọi vai

Ở chế độ công ty, Harness của team bật thêm được hai subagent chạy model rẻ. Subagent khảo sát đọc code trước khi sửa. Subagent xác minh chạy lại check và đối chiếu kết luận với bằng chứng. Mọi vai, kể cả vai chạy model API key, tìm web qua search pool của team.

Subagent khảo sát

Chỉ đọc project, không lên web và không chạy lệnh. Kết quả trả về kèm file và dòng. Agent chính giao phần đọc rộng cho nó để giữ context cho việc sửa.

Subagent xác minh

Chạy check của repo trong sandbox chỉ-đọc, không có mạng, và đối chiếu từng yêu cầu với code và nguồn gốc. Mỗi yêu cầu được trả lời là đạt, không đạt hoặc không kiểm được, kèm bằng chứng. Check nó chạy qua được tính vào quy trình của lượt.

Tìm web qua search pool

web_search hỏi search pool của Studio trước: key tìm kiếm của team, rồi tới nguồn không cần key. Nhờ vậy vai chạy model API key cũng tìm được web.

Chỉ subagent được bật

Agent chính chỉ thấy các subagent mà Harness bật. Dashboard hiện số subagent đang chạy trên số được bật.

Sandbox chạy được test của project

Sandbox đọc được file dịch tên auth.json và giấu hẳn file .env* (trừ file mẫu), nên type-check, Vitest và Next chạy được mà không lộ secret. E2E bằng Chromium của Playwright chạy qua lệnh có mạng mà bạn duyệt.

Bộ cài gọn hơn

piagent-install và piagent-setup không còn gợi ý lệnh đã bỏ ở 1.9.0. Chúng chỉ nhắc /mcp và /subagents-doctor khi lần cài đó có cài chúng.

Đã chạy thật một lượt ở chế độ công ty qua Studio. Subagent khảo sát đọc repo trước khi sửa, subagent xác minh báo 6/6 yêu cầu đạt, review không có lỗi chặn, và mọi request đều được tính usage.

Mạng theo lần duyệt

Lệnh ở chế độ công ty chạy không mạng. Khi cần cài package, agent xin chạy đúng một lệnh có mạng; thẻ duyệt ghi rõ câu lệnh và bạn cho phép một lần.

Dừng và tiếp tục

Nút Dừng có hiệu lực suốt lượt, kể cả lúc review đang chạy. Lượt bị dừng ghi rõ là đã dừng, không báo lỗi model; bấm Tiếp tục để làm tiếp từ các bước đã giữ.

Kết nối lại chế độ công ty

Nếu phần chạy của công ty đang tắt (máy vừa khởi động, vừa cập nhật), cuộc trò chuyện báo rõ và có nút Kết nối lại ngay tại chỗ.

Không lẫn vào git

Thư mục .pi/piagent-state tự có .gitignore; trạng thái chạy không còn hiện trong git status của project.

Xếp hàng khi công ty bận

Khi mọi tài khoản model của công ty đang bận, yêu cầu tự chờ tới lượt (tối đa 20 phút) thay vì báo lỗi. Lượt đang chạy hiện bước “Chờ tài khoản công ty rảnh”; nút Dừng vẫn dùng được.

Nhiều cuộc trò chuyện cùng lúc

Tạo hay gửi trong một cuộc trò chuyện không còn bị từ chối chỉ vì cuộc khác vừa đổi. Hai thư mục trùng tên (hai bản clone) hiện thêm vị trí để chọn đúng.

Dọn model không còn

piagent-doctor chỉ ra model đã cấu hình mà Pi không còn biết; piagent-model-scope --prune chỉ xoá đúng các dòng đó.

v1.6.1 · Reliability patch

UI đúng trạng thái, review repo ngoài an toàn, helper ít tốn hơn

Bản vá này giữ nguyên model và thinking level, nhưng siết chặt lifecycle để response chỉ hiện khi task thật sự hoàn tất, đồng thời giới hạn helper và quyền đọc source ngoài theo đúng session.

Conversation truth

Draft, retry và completion còn pending ở trong Activity. Chat giữ đúng thứ tự user rồi assistant và không tiếp tục hiện processing sau terminal.

External review

URL GitHub, GitLab và Bitbucket chỉ bật source checkout tối thiểu; runtime cấp quyền đọc chính xác checkout đó và vẫn chặn cache, credential, symlink escape cùng mọi mutation.

Solo-first

Direct subagent có trần một helper read-only, không auto retry/fork/worker và có giới hạn call, turn, thời gian. Kết quả thiếu bằng chứng được ghi là failure thật.

Product stabilization

Sáu thay đổi người dùng sẽ thấy

Workflow cũ vẫn chạy. Update này đưa thêm bằng chứng runtime và các gate fail-closed vào phía sau, rồi mở những projection ngắn để người dùng kiểm tra khi cần.

Runtime truth

Model, provider, thinking, context window và provenance được đọc từ runtime hoặc authenticated catalog. Fact chưa có giữ là unknown, không đoán từ tên model.

Task trajectory

Task đi qua plan, execute, verify, review, handoff và terminal bằng state có replay. Event stale, sai identity hoặc corrupt sẽ fail closed.

Recovery và resume

Lỗi được phân loại trước khi retry hoặc repair. Environment, provider, permission, policy và scope failure không bao giờ cấp quyền sửa source.

Role-bound helpers

Scout, planner, reviewer và Oracle nhận scope/tool/budget có giới hạn. Parent model được giữ nguyên; automatic worker và multi-writer vẫn tắt.

Completion receipt

Receipt chỉ approved khi trace completed, acceptance satisfied và hard gate trên working tree hiện tại pass. Thiếu verifier hoặc work plan còn pending phải giữ remaining risk.

Product views

Preflight, live status, activity inspector, efficiency và orchestration policy có output deterministic; người dùng không cần nhờ model nhớ hoặc diễn giải state.

Daily flow

Luồng dùng hằng ngày không bị phá

Giao task như trước

Dùng prompt tự nhiên (từ bản 1.9.0 /workflow đã bỏ). Không cần gọi preflight thủ công.

Runtime tự ghi nhận truth

Task Contract, context, changed files, trajectory và checkpoint được cập nhật từ hook/tool result thay vì trí nhớ của model.

Verify đúng working tree

Chỉ exact command đã quan sát, exit thành công và khớp current-tree digest mới được tính là passing evidence.

Recovery hoặc handoff có giới hạn

Source repair và transient retry có ceiling. Trường hợp không an toàn chuyển sang handoff/operator thay vì tiếp tục đoán.

Completion fail closed

Trace completed không đủ. Work plan, acceptance, changed-file integrity và verifier hiện hành phải cùng pass trước khi receipt approved.

Compatibility

Không cần đổi thói quen hoặc migrate task cũ

Task Contract vẫn là v2.

Runtime snapshot, solver, trajectory, recovery và helper state là sidecar versioned/additive. Alias command cũ vẫn hoạt động; state cũ thiếu projection mới phải hiện unknown/unavailable thay vì được nâng cấp thành success.

Host không phải sandbox

Policy giảm lỗi trong tool surface được kiểm soát nhưng không cô lập code khỏi account của operator. External và destructive action vẫn cần confirmation.

Default giữ conservative

Solver/phase tools chưa được promote khỏi shadow, helpers chưa tự dispatch, parent routing và automatic worker vẫn off cho tới khi có rollout evidence riêng.
