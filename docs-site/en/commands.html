Short commands with predictable behavior

Slash commands package policy and workflow directly, with one inspector menu for diffs, commands, safety, and context instead of many one-off commands.

Session basics

/login/model/commands/piagent-status/piagent-inspector/piagent-orchestration/usage/usage efficiency/task-preflight/context preflight/name/fresh/session

Set up a session, select a model, inspect profile, usage, or orchestration state, and decide whether a large task needs a fresh session.

Project profile

Apply a profile directly or use a deterministic selector for the profile and tech stack. Output stays compact and does not require model interpretation.

Implementation workflow

Subagents

Product visibility

Inspect runtime decisions

These commands read deterministic state without asking a model to interpret it. They are optional in the daily workflow.

Preflight before a task
/task-preflight --json Review current repository state

Inspect intent, risk, scope, runtime, solver route, phases, tool and helper recommendations, backend, approvals, and blockers before starting.

Live task status
/piagent-status

Read the Task Contract, checkpoints, verifier evidence, recovery, helpers, resume state, and terminal receipt. Approval requires the current-tree hard completion gate to pass.

Activity, diff, and context
/piagent-inspector

One menu for summary, files, commands, security, context, and toggle. A four-row panel appears automatically just above the native footer: green is healthy, yellow needs attention, and red marks failures, safety warnings, or context at 80% and above. The command reads local state without calling a model.

Sourced efficiency
/usage efficiency

Inspect context and tool utilization, verification, repair, retries, and helper usage. Runtime values that cannot be measured stay null.

Helper policy
/piagent-orchestration

Inspect the solo-first policy, read-only roles, reviewer or Oracle recommendations, owned budgets, and the one-writer invariant.

Sourced diffs, no token estimates.

The footer panel uses observed task files for fast updates; the files view computes the exact snapshot delta and marks mixed-working-tree when a task touches a file that was already dirty. Pi exposes model usage by turn and session, so per-built-in-tool tokens remain unavailable.
