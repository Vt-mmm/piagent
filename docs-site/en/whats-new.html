1.9.0: ask in plain language, the team's Harness checks

The task contract and workflow commands are gone. Company mode asks for checks and a review on its own; Stop, network commands on approval and clearer approval cards.

v1.11.0 · 2026-10-05

One-click updates, and a dashboard that works like an editor

The dashboard checks for new releases and updates Pi and Piagent together when you click. A status bar, a command palette and searchable Settings keep every action a keystroke away.

One-click update

The dashboard checks when it opens and every 6 hours. A new release shows as "Update Piagent" in the status bar; one click installs Pi and Piagent together and reopens the dashboard in a new tab. Pi always moves to the version Piagent is qualified on, and the button waits while a conversation runs.

Command palette

⌘K or Ctrl+K reaches every action, every settings section and every conversation by name, with or without Vietnamese accents. ⌘, or Ctrl+, opens Settings.

Searchable Settings

Search finds a setting by what it does; sections are grouped, with new Updates and Shortcuts sections. The status bar shows the Gateway, running conversations and the release.

v1.10.0 · 2026-10-05

The main agent asks when it is unsure, and subagents may object to a brief

When a request leaves a decision open, the main agent asks you with a card of numbered choices instead of guessing. A subagent shows its evidence when a brief drifts from the request, and a second disagreement is yours to decide. Used-up quota or a very large patch no longer stops the work.

Questions with choices

1–4 questions, each with 2–4 numbered choices, always "Other" in your own words and "Let the agent decide". Press a number to choose, Enter to send. Stop while it waits, and on "continue" the agent asks again instead of choosing for you.

Subagents object to a brief

A subagent reads your request verbatim and the plan above its brief. When the brief is wrong or drifts from the request it shows its evidence, and the main agent has to answer. A second disagreement marks the conversation "needs your decision".

Work goes on when quota runs out

A subagent whose quota is used up, or whose account rests, starts again on the Harness fallback model. A patch over 120 KB is reviewed in parts and the findings merge.

v1.9.3 · 2026-10-03

Typing Vietnamese never sends by mistake, and subagents read leaner pages

An Enter that commits accented text only finishes the word and does not send. Two quick Enters create one conversation and send one message. Subagents read less of each web page, so a news question uses far fewer tokens.

Enter while composing

With Telex, VNI or any other input method, an Enter that commits text no longer sends or creates a conversation. Shift+Enter is still a new line.

Sent exactly once

Pressing Enter twice, or Enter and then the send button, before the page updates still creates one conversation and sends one message.

Leaner page reads for subagents

A subagent reads at most 20,000 characters of a page, 12,000 by default. The main agent still reads up to 100,000.

v1.9.2 · 2026-10-03

Web work goes to the research subagent, and the chat stays put

In company mode with a research subagent, everything on the web runs on that subagent's cheaper model. The main agent receives its summary with sources. Sending a message in a long conversation no longer pulls the page to the top.

Web work for the research subagent

With a research subagent in the Harness, the main agent has no web tools. Searches and pages are read on the research subagent's model.

Which engine searched

Each search result names the engine that answered: Tavily, Exa or Parallel through the company search pool, or the model provider's own search.

The chat stays still

Sending a message no longer makes the history vanish for a moment or pull the page to the top. The header shows the number of subagents the Harness enables.

v1.9.1 · 2026-10-03

Scout and verify subagents, web search for every role

In company mode the team's Harness can enable two more subagents on cheaper models. Scout reads the code before a change. Verify runs the checks again and compares conclusions with evidence. Every role, including roles on API-key models, searches the web through the team's search pool.

Scout subagent

It reads the project only: no web, no commands. Its answers come with file and line. The main agent hands broad reading to it and keeps its own context for the change.

Verify subagent

It runs the repository's checks in a read-only sandbox without network, and compares each requirement with the code and primary sources. Each requirement comes back as pass, fail or unverifiable, with evidence. A check it passes counts toward the turn's process.

Web search through the search pool

web_search asks Studio's search pool first: the team's search keys, then keyless providers. That way roles on API-key models can search too.

Only enabled subagents

The main agent sees only the subagents its Harness enables. The dashboard shows running subagents against the number enabled.

Project tests run in the sandbox

The sandbox reads translation files named auth.json and hides .env* files outright (templates excepted), so type checks, Vitest and Next run without exposing secrets. End-to-end tests with Playwright's Chromium run as a network command you approve.

Leaner installer hints

piagent-install and piagent-setup no longer suggest commands retired in 1.9.0. They mention /mcp and /subagents-doctor only when that run installed them.

One company-mode turn ran live through Studio. The scout read the repository before the change, verify reported 6 of 6 requirements passed, review found no blocking issue, and every request was metered.

v1.9.0 · 2026-10-02

Ask in plain language; the team's Harness does the checking

The task contract and the workflow commands are gone: you ask as you would ask a colleague, and the guard still checks every tool call. Company mode runs through Agent Studio and Agent Watch; its Harness asks for checks, has a subagent review the change and sends blocking findings back to the agent. See Ecosystem.

Plain-language requests

No more /workflow, /fresh, /onboard or task contract. The guard still blocks protected files and checks permission profiles, oversized files and stale edits, and asks you before a push or publish.

The team's Harness

Studio decides whether each turn suggests or requires a plan, checks and a review. A separate subagent reviews; blocking findings go back to the agent within the team's fix rounds.

Network on approval

Company-mode commands run without network. To install a package the agent asks to run that one command with network; the card shows the exact command and you allow it once.

Stop and continue

Stop works for the whole turn, including while the review runs. A stopped turn says it was stopped, not that the model failed; Continue picks up from the steps kept.

Reconnect company mode

If the company runtime is not running (after a restart or an update), the conversation says so and offers Reconnect in place.

Out of git

.pi/piagent-state gets its own .gitignore; run state no longer shows up in the project's git status.

Waiting in line when the company is busy

When every company model account is busy, a request waits its turn (up to 20 minutes) instead of failing. The running turn shows a “Wait for a free company account” step; Stop still works.

Many conversations at once

Creating or sending in one conversation is no longer refused because another one just changed. Two folders with the same name (two clones) also show where each one is.

Clean up models that are gone

piagent-doctor lists configured models Pi no longer knows; piagent-model-scope --prune removes only those lines.

Earlier releases

The notes below describe earlier releases as they shipped. Since 1.9.0 the task contract, trajectories, completion receipts and workflow commands mentioned below are gone.

v1.8.0

Astra, Sol, and Luna in Piagent

Pi 0.87.1 exposes all three GPT-6 models through the authenticated catalog. New sessions prefer Sol High; parent routing remains opt-in.

Luna

Focused, verifiable tasks: the low tier at Medium effort.

Sol

Everyday coding: the medium and high tiers; the new-session default is High when available.

Astra

Broad or ambiguous work: the ultra tier at Extra High. Explicit pins and existing sessions stay intact.

The router selects only authenticated models and records a legacy 5.6 fallback. The old 108-session result does not measure GPT-6 performance or token savings.

v1.7.1

Long sessions with clearer context and accounting

v1.7.1 supports Pi 0.86.1, repairs session recovery, and adds waiting within an open session.

Requested waiting

Ask the agent to wait until the next useful check. The timer makes no model calls while waiting; the session must remain open.

Context and usage

Context prioritizes supported files, and usage and verification results remain bound to the correct task.

Evidence boundary

All 14 formerly failed attempts passed a separate rerun. This is not a new 108-session score or an aggregate token-saving claim.

v1.6.1 · Reliability patch

Truthful UI state, safe external review, and lower helper overhead

This patch keeps the selected model and thinking level unchanged while tightening lifecycle truth, limiting helper expansion, and granting external-source reads only to the exact checkout for the current session.

Conversation truth

Drafts, retries, and pending completion stay in Activity. Chat preserves user-then-assistant order and clears processing only at the real terminal boundary.

External review

GitHub, GitLab, and Bitbucket references activate only minimal source checkout. The runtime grants reads to that exact tree while blocking caches, credentials, symlink escape, and every mutation path.

Solo-first

Direct subagent use is capped at one read-only helper with call, turn, and runtime budgets, no automatic retry/fork/worker expansion, and truthful failure state when evidence is missing.

Product stabilization

Six changes users will notice

Existing workflows continue to work. This update adds runtime evidence and fail-closed gates behind them, plus compact projections that users can inspect when needed.

Runtime truth

Model, provider, thinking, context window, and provenance come from the runtime or authenticated catalog. Missing facts stay unknown instead of being inferred from a model name.

Task trajectories

Tasks move through plan, execute, verify, review, handoff, and terminal using replayable state. Stale, corrupt, or identity-mismatched events fail closed.

Recovery and resume

Failures are classified before retry or repair. Environment, provider, permission, policy, and scope failures never grant source-mutation authority.

Role-bound helpers

Scouts, planners, reviewers, and Oracle receive bounded scope, tools, and budgets. The parent model stays pinned; automatic workers and multiple writers remain off.

Completion receipts

A receipt is approved only when the trace is completed, acceptance is satisfied, and the current-tree hard gate passes. Missing verifiers or pending work remain visible risks.

Product views

Preflight, live status, the activity inspector, efficiency, and orchestration policy use deterministic output; users do not need a model to remember or interpret runtime state.

Daily flow

The daily workflow does not break

Assign work as before

Use a natural-language request (/workflow was retired in 1.9.0). Manual preflight is optional.

The runtime records truth

Task Contracts, context, changed files, trajectories, and checkpoints are updated from hooks and tool results rather than model memory.

Verify the exact working tree

Only observed exact commands that exit successfully and match the current-tree digest count as passing evidence.

Bounded recovery or handoff

Source repair and transient retries have ceilings. Unsafe cases return to handoff or the operator instead of continuing by guesswork.

Completion fails closed

A completed trace is not enough. Work plan, acceptance, changed-file integrity, and current verifier evidence must pass before approval.

Compatibility

No workflow rewrite or old-task migration required

Task Contract remains v2.

Runtime snapshots, solver decisions, trajectories, recovery, and helper state use additive versioned sidecars. Existing command aliases continue to work; old state without a new projection stays unknown or unavailable instead of being upgraded into success.

The host is not a sandbox

Policy reduces mistakes inside controlled tool surfaces but does not isolate code from the operator account. External and destructive actions still require confirmation.

Defaults remain conservative

Solver and phase tools remain in shadow, helpers do not auto-dispatch, and parent routing and automatic workers stay off until separate rollout evidence exists.
