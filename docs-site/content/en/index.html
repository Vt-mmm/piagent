Why it is different

The agent works fast. The platform keeps it right.

Every tool call goes through the guard, every risky action waits for you, and in company mode a turn is only reported done once checks ran on the final code.

{{icon:shield-check}}

A guard on every tool call

Fails closed: protected files, permission profiles, oversized files, edits on a stale read. When in doubt it blocks, it does not guess.

✕ read .env — protected path
✕ edit src/app.ts — read it again first
! git push — waits for one approval
✓ npm test — allowed
{{icon:check-circle}}

The team's Harness checks and reviews

Studio sets the plan, the checks and the review rounds for the whole team. A subagent reads the diff on its own; the outcome sits right under the answer.

plancheckreviewmain · research · review
{{icon:key}}

One approval at a time

Push, publish and network commands run only after you press Allow once. There is no "always allow".

{{icon:box}}

A sandbox in company mode

Seatbelt on macOS, bubblewrap on Linux and WSL2: no network, no Keychain, no .env or SSH keys.

{{icon:code}}

The dashboard is an editor

Folder tree, editor, terminal, hunk-by-hunk review, a Timeline to restore turns and /undo. 13 colour themes.

{{icon:clock}}

Install

Running in two minutes

piagent-setup installs the exact Pi release this version pins, initializes the project and runs the doctor.

01

Install

Run it in the project folder.

bash
npm install -g @piagent/platform
piagent-setup
02

Open

Terminal, or the dashboard in your browser.

bash
piagent dashboard
pi                    # Terminal
03

Update

The dashboard tells you about new releases every hour.

bash
piagent-update
