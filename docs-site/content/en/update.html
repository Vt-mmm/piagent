Update

The dashboard and Terminal check for a new release every hour. When one is out, the dashboard opens a dialog with what will change, Update now and Later (asks again in an hour). To run it yourself, one command:

Move to the latest release
piagent-update

Restart the dashboard afterwards so the new interface takes effect.

Open Terminals

There is no need to close a Terminal. After an update, every open Terminal (piagent and piagent studio) loads the new release when it is idle and keeps its conversation. A Terminal running a task waits for it to finish, and its footer says so. The personal Terminal reloads Piagent's extensions; the company Terminal starts again in the same window, on the same conversation. To ask again at any time:

Load the installed release in every open Terminal
piagent reload

When the new release runs on another Pi version, the personal Terminal says to reopen piagent.

What it does, in order

  1. Resolves the target release and the Pi version it pins.
  2. Installs that Pi host, then replaces the piagent-update helper.
  3. Checks the version actually on disk before running the installer.
  4. With --project: migrates the project's state and runs piagent-doctor --strict-share.
Not from a git checkout

piagent-update refuses to run when the global package is a link to a source repository, so it never overwrites code you are editing.

Common options

CommandUse when
piagent-update --checkYou only want to know whether a release is out.
piagent-update --dry-runYou want to see what would be installed, changing nothing.
piagent-update --version X.Y.ZYou want exactly one release, newer or older.
piagent-update --project .You want the current project migrated too.
--no-host · --no-package · --no-migrateYou want to skip a step.

Pin one release for a team

For a team rollout, install the exact Pi host and platform release, then run the installer in stable mode. The --dry-run step prints what would change.

Pinned install
npm install -g --ignore-scripts @earendil-works/pi-coding-agent@{{piHost}}
npm install -g --ignore-scripts @piagent/platform@{{version}}
piagent-install --stable --dry-run
piagent-install --stable

Installed from a package, .pi/settings.json records npm:@piagent/platform@<version>: the same value on every machine, so the team can commit it. The full procedure is in the release & install policy.

Roll back

Rolling back is deliberate, never automatic. Move to a specific release with the same update command:

Back to a previous release
piagent-update --version X.Y.Z --dry-run
piagent-update --version X.Y.Z

To change only the Pi package and keep the host: piagent-install --version vX.Y.Z --resolve-tag. Run piagent-doctor on the project afterwards.

Uninstall

piagent-uninstall only reports what it would remove and exits. It acts with --apply, because it edits Pi settings that other tools also write to.

Preview, then remove
piagent-uninstall
piagent-uninstall --apply
npm uninstall -g @piagent/platform

Add-ons, the Pi host and project state are opt-in: --with-addons, --with-host, --project <path>.

Never removed

Credentials, trust, sessions, todos and .pi/memory/ are kept under every combination of flags. Files generated from a template and then edited (AGENTS.md, .pi/settings.json) are only listed, for you to decide.

On Windows

Run the same PowerShell command you installed with: it updates WSL, Piagent and Agent Watch. See Windows.
