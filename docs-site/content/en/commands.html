Session status
/piagent-status

The session's profile, guard, runtime and model. It changes no file, reruns no check and starts no model turn.

Activity, diff, and context
/piagent-inspector

One menu for summary, files, commands, security, context, and toggle. A four-row panel appears automatically just above the native footer: green is healthy, yellow needs attention, and red marks failures, safety warnings, or context at 80% and above. The command reads local state without calling a model.

Sourced efficiency
/usage efficiency

Inspect context and tool utilization, verification, repair, retries, and helper usage. Runtime values that cannot be measured stay null.

Helper policy
/piagent-orchestration

Inspect the solo-first policy, read-only roles, reviewer or Oracle recommendations, owned budgets, and the one-writer invariant.

Sourced diffs, no token estimates.

The footer panel uses the files observed in the session for fast updates; the files view computes the exact snapshot delta and marks mixed-working-tree when a turn touches a file that was already dirty. Pi exposes model usage by turn and session, so per-built-in-tool tokens remain unavailable.

Optional skills and packages

Audit test quality, run experiment loops

Test audit
/skill:test-audit audit the tests of the billing module

The test-audit skill ships with Piagent: it stops new tests that protect no behavior and finds duplicated tests, tests tied to the implementation, and code that exists only for tests. The agent uses it when writing or changing tests; run the command to sweep a whole area.

Experiment loop
git switch -c experiment/test-speed

If you add a package with an automatic experiment loop (run_experiment, log_experiment): the guard checks each experiment command like any shell command, and lets the loop run only on an experiment/ branch or a worktree of its own, started with nothing uncommitted, because every dropped idea erases all uncommitted changes.
