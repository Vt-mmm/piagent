Workflow impact

No new command is mandatory in the daily flow

Since 1.9.0 work is assigned with a plain-language request and nothing else. /workflow, /task, /fresh and /onboard were retired together with the task contract: a session no longer records a contract, work plan, completion gate or receipt. The guard still checks every tool call.

Short answer

Say what you want, including whether the agent may edit ("read-only, do not edit", "plan first", "implement and run the tests"). The inspection commands below are optional and never start a model turn.

Command semantics

How far the inspection commands affect a workflow

CommandReads or displaysDoes not perform
/task-preflightContext and the deterministic shadow route for an intent.Does not create anything, call a model, or grant implementation authority.
/piagent-statusProfile, guard, runtime and authenticated model state.Does not edit files, rerun verification or retry work.
/piagent-inspectorChanged files in the four-row footer panel, current tool, command failures and blocks, safety warnings, and context budget. No argument opens the menu.Does not edit files, execute commands, or estimate tokens for each built-in tool.
/usage efficiencySourced context telemetry; unavailable facts remain null or unavailable.Does not grade a person or model.
/piagent-orchestrationCurrent mode, helper mode, helper limit, review lenses, Field Guide, and writer policy.Does not change mode, spawn a helper, or enable parallel writers.
Only explicit opt-in changes behavior.

These five commands are read-only. Behavior changes only when an operator deliberately enables a setting such as helper mode; parent routing, automatic workers, and multiple writers do not turn on automatically.

Daily example

A complete flow can look like this

Inspect → implement → review
/task-preflight --json Fix the failing checkout test
Fix the failing checkout test and run the project tests.
/piagent-inspector
Review the current diff: correctness, missing tests, scope drift. Read-only.
/usage efficiency

Only the plain-language lines start model work. Preflight, inspector and efficiency are optional views.

Git in Pi Agent

There is no /git namespace and no workflow command. Ask for a commit or a pull request in plain language. git push, GitHub writes and broad staging such as git add -A still require operator confirmation.

Parent-direct orchestration

Use /piagent-orchestration to inspect the helper ceiling, dispatch/skip reason, review lenses, Field Guide, and writer policy. Helpers default to off. With explicit opt-in the parent may use up to two fresh read-only helpers; token-saving estimates are telemetry, not a gate. Workers and retries stay disabled.
